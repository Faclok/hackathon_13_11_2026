# Согласование переводов: действующие правила

14 ноября 2026. Последние прямые уточнения пользователя заменяют прежнюю модель подтверждений/отказов.

## Принятия и большинство

В неопределённом состоянии показывается один перевод. Участник подтверждает его, предлагает свой текст или пропускает. Отдельного учёта отказов нет: Confirm создаёт одно положительное утверждение о показанном варианте; Correct — одно о предложенном тексте; Skip не создаёт утверждения. Множественный выбор не реализован.

Для большинства учитывается последнее принятие участника **по случаю целиком**, а не отдельный независимый голос за каждый когда-либо выбранный вариант. Старые отправки сохраняются для истории и доверия. Пропуск не стирает предыдущее принятие.

`support(V) = уникальные участники, последнее принятие которых — V / уникальные участники с каким-либо принятием по случаю`.

85 принявших A и 15 принявших B дают 85% и 15%. При отсутствии принятий процент null. Исторические строки отказов от предыдущей реализации сохранены, но из расчётов исключены. Вес доверия в большинстве не используется.

## Выборка и охват

Каждый кандидат должен получить собственную независимую выборку: не менее N уникальных участников, которым он был действительно показан и которые дали определённый ответ. Автор своего исправления в эту независимую выборку не входит. N старого текста не переносится на новый кандидат.

Дополнительно проверяются школы/классы и максимальные доли групп среди принявших кандидата. Группы берутся из исторической выдачи, а не текущего зачисления. Границы N и порога включительны. При равном максимуме нескольких подходящих кандидатов случай передаётся эксперту; произвольный ID победителем не становится.

Участники без школы входят в общий N и процент принятий. У их выдачи SchoolId/ClassId действительно null; отдельной фиктивной школы нет. Минимальный охват и доли групп рассчитываются только по реальным школьным участникам: самостоятельные аккаунты не увеличивают число групп и не разбавляют концентрацию одной школы. Без требуемого школьного охвата автоматического принятия нет; достаточно оценённый случай доступен эксперту.

Настройки версионируются администратором. Начальные значения: N=100, 80%, 2 школы, 3 класса, доли школы/класса 60%/40%, 30 минут выдачи, повтор через 24 часа, рабочий набор 20. Нехватка аудитории не ослабляет квоты автоматически.

Распределитель учитывает живые резервы и историю. Внутри выбранного случая кандидаты показываются по одному, с приоритетом меньшего числа показов; своё исправление автору не выдаётся. Небольшая новая выборка не отменяет старый результат сама по себе: старый вариант остаётся принятым, пока соответствует требованиям большинства и охвата. Если требования утрачены, а победителя нет, сохраняется редакция Pending и случай становится спорным.

## Решения и эксперт

Решение сообщества содержит один основной вариант и не закрывает случай. Новые ответы продолжают поступать и пересчитываться. Каждая смена решения сохраняет ResolutionRevision: номер, политику, результат и доказательства.

Эксперт видит очередь, оригинал, источник и статистику вариантов; может выбрать любой доступный ему случай, добавить свой текст и установить один основной плюс 0..4 дополнительных допустимых. Он отдельно перечисляет явно неверные варианты. Остальные остаются неопределёнными; «не победил» не означает «неверен».

Эксперт отправляет ожидаемую ревизию. Устаревшая ревизия даёт 409. Экспертное закрытие окончательно для обычного пересчёта. Поздний ответ по ранее выданному заданию архивируется, без изменения решения и доверия; новых выдач закрытого случая нет.

## Доверие

Формула остаётся `(correct + 5) / (total + 10)`. Для каждой допустимой исторической отправки учитывается одно положительное утверждение. Если ученик отверг A и предложил B, а эксперт признал оба неверными, получается одна ошибка за B, без отдельного бонуса за A. Дополнительный допустимый вариант так же правилен, как основной.

Принятый вариант даёт (correct=1,total=1), явно неверный — (0,1), ещё не определённый — (0,0). При потере определённого результата прежние вклады сохраняются **до нового определённого решения**, как подтвердил пользователь. Исходные снимки доверия и история неизменны.

Новый итог = прежний итог − прежний вклад + новый вклад. TrustAssessment хранит историю, TrustContribution — текущий вклад. Повтор и старое сообщение не начисляют вклад заново: обработчик читает текущую редакцию случая. Новые ответы оцениваются и при неизменном принятом результате. Архивные ответы после эксперта исключаются.

Ответ и Outbox сохраняются одной транзакцией. Фоновый обработчик применяет согласование, доверие и подтверждение обработки вместе. Ошибка одного случая не блокирует остальные; неудачная операция остаётся в очереди. Параллельные случаи одного участника не теряют изменения счётчиков.

## Экспорт

Формат исходного ТЗ: fragment_id, text_ba, lang_pair, translation, source, confirmed, status. **confirmed — число уникальных участников, принявших основной вариант**, а не Boolean. status — confirmed либо expert_review. По умолчанию экспортируются определённые непротиворечивые результаты; includeDisputed добавляет спорные случаи. Доступ проверяется по глобальной, собственной поставщицкой или конкретной case-области. Выгрузка использует согласованный снимок БД.
