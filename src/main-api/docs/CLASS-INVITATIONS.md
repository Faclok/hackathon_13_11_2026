# Самостоятельная регистрация и приглашение в класс

Ученик регистрируется через существующий `POST /auth/register` с `username` и `password`, затем входит через `/auth/sign-in`. Школа, email и Telegram не обязательны. Учитель приглашает по точному логину (без учёта регистра); ученик принимает или отклоняет приглашение в своём аккаунте.

Все маршруты ниже требуют JWT:

| Маршрут | Пользователь | Тело / результат |
| --- | --- | --- |
| `POST /api/classes/{classId}/invitations` | Учитель этого класса | `{"username":"student"}` → 201, приглашение |
| `GET /api/classes/{classId}/invitations` | Учитель этого класса | Список приглашений с решениями |
| `GET /api/me/class-invitations` | Ученик | Только свои приглашения |
| `POST /api/me/class-invitations/{id}/response` | Адресат | `{"accept":true}` или `{"accept":false}` → 200, приглашение |

Списки принимают `offset` (от 0) и `limit` (1–100, по умолчанию 50). Ответ содержит `id`, `classId`, `className`, `schoolId`, `schoolName`, `teacherId`, `teacherUsername`, `participantId`, `participantUsername`, `status`, `createdAt`, `respondedAt`. Статусы: `Pending`, `Accepted`, `Declined`, `Cancelled`.

До подтверждения ученик остаётся самостоятельным участником: приглашение не даёт учителю доступа к восстановлению пароля. При подтверждении сохраняются аккаунт, пароль, сессии, ParticipantId, Telegram-привязка и история; создаётся членство в классе. Затем применяется обычное правило восстановления доступа учителем своего класса. В интерфейсе подтверждения следует показать школу, класс, логин учителя и это право учителя.

Учитель должен владеть классом и иметь `students.create` в школе. Приглашать можно активного самостоятельно зарегистрированного участника без класса и без привилегированных назначений. При принятии условия проверяются повторно. Существующее членство не переносится и не перезаписывается. Старые выдачи и их снимки школы/класса не изменяются; новые используют подтверждённое членство.

Повторное приглашение в тот же класс возвращает прежнее ожидающее приглашение. Повтор одинакового ответа возвращает принятое решение без второго членства и аудита; противоположный ответ — 409. После отказа учитель может отправить новое приглашение. Принятие отменяет остальные ожидающие приглашения ученика. Приглашения хранятся без автоматического срока истечения; отдельные уведомления вне API не отправляются.

Неверное тело/пагинация — 400, отсутствие JWT — 401, чужой класс или недостаточные права — 403, неизвестный логин/недоступное приглашение — 404, существующий класс или конфликт решения/параллельной операции — 409. После параллельного конфликта клиент перечитывает состояние. Глобальные административные права сами по себе не разрешают приглашать от имени чужого учителя.

Миграция `ClassInvitations` добавляет таблицу, внешние ключи и уникальность ожидающего приглашения для пары класс–ученик. Примеры: [class-invitations.http](../src/BashkirSchool.Host/class-invitations.http).

Интерфейс доступен в рабочем кабинете `/test/`: самостоятельная регистрация — во «Вход и регистрация», отправка и список приглашений — в «Школа и пользователи» учителя, принятие и отказ — в «Мой класс» ученика. Перед принятием требуется отметить согласие с указанием школы, класса, логина учителя и его права восстанавливать доступ. Пошаговая инструкция: [USAGE.md](../../../client/test/USAGE.md#самостоятельная-регистрация-и-приглашение-в-класс).
