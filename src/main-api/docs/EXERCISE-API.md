# Задания: договор с клиентом и расширение

14 ноября 2026. Все маршруты `/api` требуют JWT. Автор и права определяются сервером. Клиент не передаёт ключ, правильность или доверие.

## Проверка перевода

Обучение организовано как [личные уровни и боссы](LEVELS.md), `/api/learning/*`. Дневные маршруты удалены. Каждые пять уровней открывается необязательный босс из трёх разных фрагментов. Новые проверки выдаются только для неопределённых переводов.

`POST /api/reviews/next?kind=translation-choice` выдаёт основной режим: предложение и от одного до четырёх популярных переводов. `options` содержит `{id, text}`, `allowCustom=true`. Ранжирование — число последних принятий уникальных участников, затем время создания и ID. Нулевые выборки имеют такой же детерминированный порядок. Формулировки самого проверяющего не выдаются ему для независимой проверки.

Ответ: `POST /api/reviews/{id}/response`:

```json
{"action":"Confirm","selectedVariantId":"<ID из options>"}
```

или собственный перевод:

```json
{"action":"Correct","correction":"Собственный перевод"}
```

`Skip` сохраняет прежний смысл. Нельзя одновременно выбрать вариант и отправить исправление. Каждый ответ даёт ровно одно принятие. Список показанных вариантов сохраняется; появление новых кандидатов его не меняет. В расчёте независимых показов учитывается весь показанный набор.

`kind=translation-confirm` — прежнее подтверждение одного перевода или исправление. Отсутствие `kind` сохраняет этот режим для существующих клиентов. Если есть незавершённая выдача, сервер возвращает её независимо от запрошенного режима: клиент отображает полученный `kind`.

## Учебные упражнения

- `GET /api/exercises/kinds` — зарегистрированные строковые коды и версии схем. Это каталог учебных упражнений; два режима проверки переводов выше используют отдельный процесс принятий.
- `POST /api/learning/current` создаёт или возобновляет текущий уровень из 6–10 вопросов. Клиент получает один вопрос с `id`, `attemptToken`, `kind`, `schemaVersion`, `prompt`.
- `POST /api/learning/levels/{levelId}/questions/{questionId}/answer` принимает `{"attemptToken":"...","answer":{...}}`. Правильный ответ завершает вопрос, ошибка переносит его в конец очереди. Ниже указан внутренний объект `answer`.
- Ключи ответов хранятся на сервере. В новой версии аудиозаданий исходный текст доступен по нажатию на плеер или кнопку подсказки; сборка предложения не раскрывает порядок. Клиент не выбирает будущий вопрос или уровень.

| kind | prompt | answer |
| --- | --- | --- |
| `translation-text` v2 | `text`, `sourceLanguage`, `targetLanguage`, три `options`, `wordHints`, `hintTranslation` | `{"optionId":"..."}` |
| `word-match` | `left`, `right`: по 5 `{id,text}`; `languagePair` | `{"pairs":[{"leftId":"...","rightId":"..."}, ...]}`: ровно 5 пар, каждый ID ровно один раз |
| `audio-dictation` v2 | `audioId`, `audioUrl`, `original`, три `options` на языке записи | `{"optionId":"..."}` |
| `audio-translation` v2 | `audioId`, `audioUrl`, `original`, три `options` на целевом языке | `{"optionId":"..."}` |
| `missing-word` | `before`, `after`, `options`, `allowCustom` | `{"optionId":"..."}` либо `{"text":"слово"}` |
| `sentence-order` | `tokens`: перемешанные `{id,text}` | `{"tokenIds":["...","..."]}` в нужном порядке |

Ранее выданные упражнения `translation-text`, `audio-dictation` и `audio-translation` версии 1 сохраняют текстовый ответ. Новые вопросы этих видов имеют версию 2 и проверяют только ID одного из трёх выданных вариантов. Для подсказок слов используются существующие словарные пары; если их нет, интерфейс даёт открыть перевод всей фразы.

Ответ 200: `{attemptToken, recognized, levelCompleted, correctAnswer}`. При ошибке в задании с выбором возвращается правильный вариант. После ответа клиент повторно вызывает `/api/learning/current`. Повтор использованного токена с тем же ответом возвращает прежний результат; другой ответ с этим токеном — 409. Чужой уровень — 404, неверная структура — 400. `recognized=false` означает отсутствие совпадения с сохранённым ключом, а не экспертное признание формулировки неверной. Учебные ответы не создают голоса и не меняют доверие. Сравнение текстов буквальное; одинаковые слова в сборке взаимозаменяемы, но каждый ID используется один раз.

## Подготовка материалов

Временный импорт словаря через экспертный кабинет: любой вошедший пользователь отправляет `POST /api/vocabulary`. По прямому указанию пользователя проверка `content.deliver` для этого маршрута снята; действующая сессия по-прежнему обязательна:

```json
{"languagePair":"ba-ru","entries":[{"word":"бер","translation":"один"}]}
```

От 1 до 500 пар за запрос; повтор пары возвращает прежний ID. Для задания нужны пять разных слов и пять разных переводов. Неоднозначные одинаковые надписи в одной выдаче не используются. Словарные данные должны быть заранее проверены поставщиком; импорт не запускает словарный консенсус.

`POST /api/cases/{caseId}/audio` явно готовит озвучку; доступен поставщику или участнику с `lessons.receive`. Возвращает `{id,fragmentId}` после успешной загрузки. Этот вызов необязателен: при создании уровня недостающие записи для выбранных аудиовопросов готовятся автоматически. Первый запрос может ждать загрузки модели и синтеза; повторное чтение уровня использует сохранённые вопросы и записи. Если подготовка не удалась, уровень собирается из остальных доступных упражнений; если таких нет, возвращается `204` без создания пустого уровня. При отсутствии определённого перевода фрагмент не используется ни в одном учебном виде, включая диктант; это не запрещает заранее подготовить его аудио.

## Silero и S3-хранилище

Модель — `v5_cis_base`, CPU, по умолчанию `bak_aigul` и 24000 Гц. C# через `System.Diagnostics.Process` запускает приватный локальный worker; отдельного сетевого TTS-сервиса нет. Пакет модели использует Python/PyTorch, поэтому простой вызов `torch.jit.load` или загрузка пакета как ONNX не подменяет официальный загрузчик. Dockerfile включает Python, CPU PyTorch 2.8.0 и NumPy 2.3.3.

Модель скачивается с официального адреса только при первом некэшированном синтезе; можно заранее положить файл по `Speech:ModelPath`. Worker создаётся лениво, обрабатывает запросы последовательно и сохраняет модель в памяти. При ошибке/тайм-ауте процесс завершается, следующий запрос может запустить его заново. При остановке приложения worker завершается вместе с ним. Библиотека `v5_cis_base` рассчитана на расстановку ударений в подготовленном тексте; автоматическая расстановка здесь не добавлена.

Ключ S3 зависит от исходного текста, языка, голоса, частоты и `Speech:ModelRevision`. Одинаковые исходники разных поставок используют один файл. Проверка существования объекта предотвращает повторный синтез, в том числе после сбоя между загрузкой и записью в БД; отсутствующий объект можно восстановить. Новая настройка голоса/ревизии создаёт другой объект и сохраняет прежнюю запись для выданных упражнений. При замене весов модели увеличьте `ModelRevision`.

В production используется Garage в Coolify со стандартным AWS SDK и path-style адресацией. Перед первым запросом TTS создайте приватный bucket `school-audio` в Garage и выдайте ключу из `AudioStorage:AccessKey` права `read` и `write` на него. Автоматический bucket Garage называется `default`, если при создании сервиса не задано другое имя; он не заменяет `school-audio`. Для Garage загрузка WAV выполняется без chunked encoding, чтобы подпись тела запроса проверялась корректно. Клиент получает подписанную GET-ссылку, обновляемую при чтении текущего уровня. В БД хранится ключ объекта, а не истекающая ссылка. `AudioStorage:Endpoint` — `https://s3.bashperevod.ru`, регион — `garage`; адрес должен быть доступен браузеру и main-api. Подмена хоста в уже подписанной ссылке недопустима.

Настройки — `Speech:*` и `AudioStorage:*` в [appsettings.json](../src/BashkirSchool.Host/appsettings.json), переменные — [container.env.example](../container.env.example). В Coolify нужен постоянный записываемый том `/app/models`, Python из Dockerfile и параметры Garage. Учётные данные передаются секретами окружения. Без настройки S3 остальные виды работают, запрос аудио сообщает ошибку конфигурации.

## Добавление нового вида

1. Реализовать `IExerciseHandler`: уникальный `Kind`, `SchemaVersion`, требования к материалу (`RequiresSentence`, `RequiresAudio`, `RequiresAcceptedTranslation`), `Create` и `Evaluate`.
2. Описать отдельные типы публичного условия, приватного ключа и ответа. `Create` возвращает их JSON-снимки; `Evaluate` проверяет ответ по сохранённому ключу, не обращаясь к изменившемуся материалу.
3. Зарегистрировать обработчик через `AddSingleton<IExerciseHandler, NewHandler>()`; при необходимости включить код в `Learning:Kinds`. Общие выдача, владение, хранение и повторная отправка не меняются.
4. Для изменения схемы оставить обработчик старой версии зарегистрированным, добавить новую версию. Новая выдача использует последнюю, старая попытка проверяется своей сохранённой версией.

Новая механика с новым источником материалов потребует расширения загрузки `ExerciseMaterial`. Реестр не обещает автоматически поддержать произвольные новые данные.
