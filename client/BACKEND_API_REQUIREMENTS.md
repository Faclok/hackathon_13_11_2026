# API, необходимый клиенту «Башкирская языковая школа»

Дата: 14 ноября 2026 года.

Статус: предлагаемый контракт под текущий игровой интерфейс. Документ описывает потребности клиента, а не существующие методы бэкенда. Пути методов можно согласовать при интеграции.

## 1. Вход и сессия

| Метод | Что делает | Что возвращает |
| --- | --- | --- |
| `POST /api/auth/login` | Вход пользователя. Способ авторизации нужно согласовать: сейчас в интерфейсе вводится только ник. | Токены, сроки их действия и профиль пользователя. |
| `POST /api/auth/refresh` | Обновляет сессию по `refreshToken`. | Новые токены и сроки действия. |
| `POST /api/auth/logout` | Завершает текущую сессию. | Подтверждение выхода. |

Ввод одного ника в демо не определяет способ авторизации реальных пользователей. Формат запроса входа нужно согласовать отдельно.

## 2. Профиль и главная

| Метод | Что делает | Что возвращает |
| --- | --- | --- |
| `GET /api/me` | Загружает текущего игрока. | Имя, аватар, уровень, XP, монеты, серию, статистику, трофеи, купленные и применённые украшения. |
| `GET /api/home` | Загружает данные главной страницы. | Серию занятий, семь отметок активности, фразу дня с переводом. |
| `GET /api/trophies` | Загружает справочник трофеев. | Название, описание, иконку, редкость и условие получения каждого трофея. |

Пример данных игрока:

```json
{
  "id": "user-1",
  "nick": "Денис",
  "avatarUrl": "/avatars/denis.svg",
  "level": 16,
  "xp": 1540,
  "xpToNextLevel": 60,
  "coins": 2400,
  "caseKeys": 0,
  "streak": 42,
  "tasksSolved": 700,
  "accuracy": 96,
  "rank": "Батыр",
  "langPair": "ba-ru",
  "trophyIds": ["first", "week"],
  "ownedDecorationIds": ["mint", "green", "honey"],
  "appearance": {
    "backgroundId": "mint",
    "frameId": "green",
    "hatId": null,
    "petId": null,
    "itemIds": ["honey"]
  }
}
```

Позиции предметов на фоне сейчас определяет клиент. От бэкенда достаточно списка отображаемых предметов.

Семь отметок активности должны содержать даты и признак занятия, чтобы клиент мог отобразить выполненные и оставшиеся дни.

## 3. Мини-игра и уроки

Ежедневная карточка открывает мини-игру. Отдельный API проверки ежедневного перевода для текущего интерфейса не нужен.

| Метод | Что делает | Что возвращает |
| --- | --- | --- |
| `GET /api/learning/units` | Загружает карту обучения. | Разделы, уроки, общий прогресс и состояния уроков: доступен, закрыт, пройден. |
| `POST /api/learning/lessons/{lessonId}/attempts` | Начинает прохождение урока. | `attemptId`, упражнения и текущий прогресс. |
| `POST /api/learning/attempts/{attemptId}/answers` | Принимает ответ на упражнение и проверяет его. | Результат проверки, пояснение и правильный вариант после ответа. |
| `POST /api/learning/attempts/{attemptId}/complete` | Завершает урок и начисляет награды. | Точность, ошибки, полученные XP и монеты, новые трофеи и обновлённый прогресс. |
| `GET /api/learning/attempts/{attemptId}` | Восстанавливает прохождение или показывает его результат после перезагрузки. | Состояние попытки, сохранённые ответы и результат, если урок завершён. |

Нужны три типа упражнений:

| Тип | Что выдаёт сервер | Что отправляет клиент |
| --- | --- | --- |
| `choice` | Фразу и варианты перевода с ID. | ID упражнения и выбранного варианта. |
| `match` | Два списка слов с ID. | ID упражнения и составленные пары ID. |
| `order` | Предложение на русском и перемешанные слова с ID. | ID упражнения и ID слов в выбранном порядке. |

Правильные ответы проверяет сервер. Клиент отправляет выбранные варианты, а не самостоятельно рассчитанный балл. До ответа сервер не передаёт ключи проверки, порядок правильного предложения или готовые соответствия для поиска пар.

В результате урока нужны:

- число выполненных упражнений и число верных ответов;
- точность в процентах;
- список ошибок с правильными вариантами;
- фактически начисленные XP и монеты;
- полученные трофеи;
- обновлённые данные игрока и прогресс уроков.

## 4. Испытание Босса

Испытание состоит из **трёх фраз**. Для каждой фразы пользователь выбирает один из трёх переводов либо предлагает свой.

Доступ только для трёх старших званий, начиная с «Оста»: минимум 250 решённых заданий и серия от 14 дней. «Батыр» и «Аҡыл эйәһе» также имеют доступ. Сервер проверяет требования при начале испытания, при отправке ответа и завершении сессии; недостаточное звание — HTTP 403 с кодом `BOSS_RANK_REQUIRED`. Проверка в игровом интерфейсе и мок-API уже используется, но не заменяет серверную авторизацию. Нужны сложные фрагменты из корпуса, а не приветствия из начального урока; вместе с фразой возвращаются ID фрагмента и сведения об источнике.

| Метод | Что делает | Что возвращает |
| --- | --- | --- |
| `POST /api/boss/sessions` | Начинает испытание из трёх фраз. | `sessionId`, фразы, ID раундов и по три варианта перевода. |
| `POST /api/boss/sessions/{sessionId}/answers` | Принимает выбранный вариант или свой перевод. | Подтверждение принятия; при необходимости — распределение голосов после ответа. |
| `POST /api/boss/sessions/{sessionId}/complete` | Завершает испытание. | Количество совпадений с популярным вариантом, XP, монеты и полученные трофеи. |

Ответ с выбранным вариантом:

```json
{
  "roundId": "round-1",
  "optionId": "option-2"
}
```

Свой перевод:

```json
{
  "roundId": "round-1",
  "customText": "Мой вариант перевода"
}
```

В одном ответе передаётся либо `optionId`, либо `customText`.

В Боссе не нужен признак «правильный ответ»: интерфейс показывает принятие ответа и мнение сообщества. Собственный перевод пользователя сохраняется на сервере. Если показываем распределение голосов, оно возвращается после принятия ответа.

## 5. Рейтинг

| Метод | Что делает | Что возвращает |
| --- | --- | --- |
| `GET /api/leaderboard?period=global&metric=tasks&offset=0&limit=20` | Загружает рейтинг с фильтрами и постраничной выдачей. | Участников с местами и значениями показателя, общее количество участников и отдельную строку текущего игрока. |

Параметры:

- `period`: `global` или `monthly`;
- `metric`: `tasks` или `streak`;
- `offset`, `limit`: постраничная выдача.

Для каждого участника нужны:

- `id` — ID игрока;
- `nick` — отображаемое имя;
- `avatarUrl` — аватар;
- `level` — уровень;
- `rank` — место в выбранном рейтинге;
- `value` — значение выбранного показателя;
- `trophyIds` — полученные трофеи;
- `appearance` — применённый фон, рамка и предметы на фоне.

Здесь `rank` — место в рейтинге. Поле `rank` в примере профиля выше — звание; при окончательном согласовании DTO лучше назвать их раздельно: `position` и `title`.

Фон, рамка и предметы должны возвращаться в рейтинге, чтобы покупки сразу отражались в карточке игрока. Полный приватный инвентарь других участников для отображения рейтинга не нужен.

Собственная строка возвращается даже тогда, когда пользователь не входит в запрошенную страницу списка.

Первое место Дениса — настройка демо-данных. Сам рейтинг должен рассчитывать сервер.

## 6. Инвентарь, ключи, кейсы и оформление

| Метод | Что делает | Что возвращает |
| --- | --- | --- |
| `GET /api/me/inventory?type=background` | Загружает только принадлежащие игроку украшения. | ID, тип, название, описание, редкость, превью и данные оформления. |
| `GET /api/cases` | Загружает четыре тематических кейса и условия получения ключей. Кейс «Питомцы и предметы» содержит шесть новых питомцев и шесть культурных предметов; старые питомцы больше не выпадают. | ID, тип, доступные типы наград (`dropTypes`), название, изображение, список возможных наград с вероятностями, цена ключа и компенсация за дубликат. |
| `POST /api/case-keys/purchases` | Покупает универсальные ключи за монеты по `quantity`. | Актуальный единый баланс монет и количество ключей. |
| `POST /api/cases/{caseId}/open` | Расходует один ключ и определяет награду. | ID открытия, выпавший предмет, признак дубликата, компенсацию, актуальные баланс, ключи и инвентарь. |
| `GET /api/me/case-openings?limit=3` | Восстанавливает результат открытия после перезагрузки и загружает последние находки. | Сохранённые результаты открытий. |
| `PATCH /api/me/appearance` | Применяет или снимает принадлежащий игроку фон, рамку, головной убор, питомца или предмет на фоне. | Обновлённое оформление. |

Возможные значения `type`: `background`, `frame`, `hat`, `pet`, `item`. Прямая покупка украшений убрана: за монеты покупаются только универсальные ключи, а украшения выпадают из кейсов. В инвентаре нет недоступных предметов на продажу.

Текущие настройки демо: один ключ стоит 10 монет, каждый кейс требует один ключ. Веса редкостей: обычный — 45, редкий — 30, эпический — 18, легендарный — 7. Веса нормализуются среди представленных в кейсе редкостей; предметы одной редкости равновероятны. API должен возвращать итоговый шанс каждого предмета в процентах. Повторный предмет не дублируется в инвентаре, вместо него начисляется 5 монет. Старые покупки остаются собственностью игрока.

Данные позиции каталога:

- `id`;
- `type`;
- `title`;
- `description`;
- `rarity`: `common`, `rare`, `epic`, `legendary`;
- `previewUrl` — символьное превью для старых предметов;
- `imageUrl` — необязательная ссылка на иллюстрацию (для новых SVG-фонов, питомцев и предметов);
- `isDefault` — базовый предмет;
- ключ оформления, известный клиенту, либо ссылка на графический ресурс.

Пример покупки ключей:

```json
{
  "quantity": 5
}
```

Пример переключения оформления:

```json
{
  "backgroundId": "ornament-emerald",
  "frameId": "frame_neon_leaf",
  "hatId": "hat_tubeteika",
  "petId": "pet_bee",
  "itemIds": ["honey"]
}
```

Для оформления каталог должен передавать ключ известного клиенту дизайна — например, `ornament-emerald` — либо ссылку на графический ресурс. Одного названия и эмодзи недостаточно.

Сервер проверяет баланс, наличие ключа и владение применяемым украшением. Покупка ключей, расход ключа, выдача награды и компенсация за повтор должны быть атомарными и идемпотентными. Награда сохраняется до запуска визуальной анимации: закрытие страницы не отменяет выдачу и не требует повторного открытия. Выбор результата и начисление компенсации выполняет сервер; анимация только показывает полученный результат. Снятие рамки, головного убора или питомца передаётся как `null` в соответствующем поле. Применение и снятие предметов не списывает монеты. Инвентарь, ключи и оформление сохраняются между сессиями и устройствами.

## 7. Сообщения об ошибках

| Метод | Что делает | Что возвращает |
| --- | --- | --- |
| `POST /api/reports` | Принимает сообщение об ошибке в упражнении или фразе Босса. | ID обращения и подтверждение сохранения. |

Пример сообщения об упражнении:

```json
{
  "targetType": "exercise",
  "targetId": "exercise-1",
  "attemptId": "attempt-1",
  "text": "В вариантах ответа опечатка"
}
```

Для сообщения о фразе Босса передаются соответствующий `targetType`, ID фразы и `sessionId`. Автор и время обращения определяются сервером.

## 8. Общие требования

- Данные передаются в JSON. Идентификаторы клиент обрабатывает как строки.
- Защищённые методы определяют пользователя по сессии, а не по переданному клиентом `userId`.
- XP, монеты, серию, покупки и награды рассчитывает сервер.
- Повторная отправка запроса не должна повторно списывать монеты или начислять награду. Для изменяющих запросов нужен согласованный механизм идемпотентности.
- После покупки и завершения задания сервер возвращает актуальные изменённые данные игрока.
- Для дневной активности используется согласованный часовой пояс — сейчас `Europe/Moscow`.
- Ошибки имеют единый формат: `code`, `message`, при необходимости `fieldErrors`.
- Нужно различать отсутствие авторизации, отсутствие доступа, отсутствие ресурса, некорректный ответ, недостаток монет и конфликт состояния попытки.
- Аватары и графические ресурсы должны быть доступны клиенту по возвращаемым ссылкам.

Раздел «Барабан» теперь содержит кейсы с наградами и покупку ключей. Отдельного баланса монет у него нет.
