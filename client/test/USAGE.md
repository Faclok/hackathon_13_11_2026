# Как пользоваться Башпереводом

Рабочий кабинет открывается по адресу `/test/` (например, `https://bashperevod.ru/test/`). На главной странице `/` работает новый интерфейс. Кабинет обращается к существующим API ядра и LMS на том же домене.

## Как устроен кабинет

- **Слева** — рабочее пространство и его разделы. На экране открыт только один раздел.
- **Сверху** — текущий аккаунт. Здесь можно выбрать другой уже сохранённый аккаунт либо нажать «Войти в другой аккаунт».
- **На главной** — рекомендуемый следующий шаг.
- **В результате действия** — понятное сообщение или таблица. JSON, идентификаторы и журнал убраны в «Технические данные» и «Проверка подключения».

Рабочие пространства:

| Пространство | Что находится в меню |
| --- | --- |
| Участник | Проверка переводов, практика перевода, вводный курс, свой аккаунт |
| Администратор | Быстрый старт, школа и пользователи, доступ, правила распределения |
| Учитель | Свои классы, ученики и установка паролей |
| Поставщик материалов | Добавление фраз и переводов |
| Эксперт | Очередь и окончательное решение по переводам |
| Экспортёр | Выгрузка переводов |

Пространство — это настройка интерфейса, а не выдача прав. Если у аккаунта нет разрешения, сервер отклонит действие даже в выбранном пространстве. У ранее сохранённых аккаунтов может ещё не быть выбранного пространства: задайте его слева, заново регистрироваться не нужно.

## Запуск после обновления

В Coolify пересоберите приложение из обновлённых исходников. Контейнер `client` собирает основной интерфейс и кабинет `/test/`, `nginx` направляет `/` и `/test/` в клиент, `/auth/*`, `/api/*`, `/health/*` — в соответствующие API. Убедитесь, что переменные ядра заполнены по инструкции в `src/main-api/docs/INTEGRATION.md`. Этот клиент не создаёт и не заменяет серверную конфигурацию.

Локальная сборка: в каталоге `client` выполните `npm ci`, затем `npm run build`. Для разработки предусмотрен `npm run dev`: он использует Vite proxy на локальные API (по умолчанию ядро `http://127.0.0.1:5105`, LMS `http://127.0.0.1:5093`). Переопределение: `CORE_API_URL` и `LMS_API_URL` в окружении процесса Vite. Сами API и PostgreSQL должны быть запущены отдельно.

## Первый вход

1. Для обычного участия откройте «Вход и регистрация» → «Зарегистрироваться». Для существующего аккаунта оставьте «У меня есть аккаунт».
2. Введите логин и пароль. В форме входа выберите «Мои задачи» — например, «Администратор». Нажмите «Войти в кабинет».
3. Для администратора используйте `BOOTSTRAP_USERNAME` / `BOOTSTRAP_PASSWORD`, заданные при первом запуске пустой базы. Изменение bootstrap-пароля в окружении не меняет уже созданный пароль в БД.
4. Откроется главная с рекомендуемой задачей. Все следующие действия выполняются от аккаунта в верхнем списке. Администратор не является автоматически экспертом или участником.

Если нужно проверить соединение, внизу меню нажмите «Проверить подключение», затем одноимённую кнопку. У исправных сервисов появится «Работает»; в технических данных ядра будут `alive` и `ready`, LMS — `ok`. Эта проверка не подтверждает права пользователя.

Пароли: минимум 12 символов, прописные и строчные буквы, цифра и спецсимвол. JWT signing key не является паролем администратора и в интерфейс не вводится.

## Полный сценарий без ручного ввода ID

1. Под администратором выберите пространство «Администратор» и откройте «Быстрый старт».
2. Оставьте автоматически созданный уникальный префикс, задайте пароль для новых аккаунтов и нажмите «Создать аккаунты и первый материал».
3. Дождитесь списка созданных объектов. Будут созданы школа, учитель, класс, ученик, самостоятельный участник, поставщик, эксперт, экспортёр и фрагмент `Һаумыһығыҙ` → `Здравствуйте`. У всех новых аккаунтов — введённый вами пароль. Логины имеют суффиксы `-teacher`, `-student`, `-participant`, `-producer`, `-expert`, `-exporter`.
4. По завершении выбран самостоятельный участник и его пространство. Главная предложит «Получить задание». Перейдите в «Проверка переводов» и получите фразу. Нажмите «Перевод верный», «Не знаю — пропустить» либо раскройте «Перевод нужно исправить» и отправьте свой вариант.
5. Статистика находится в сворачиваемом блоке «Посмотреть статистику перевода». ID подставляется автоматически. На существующей базе распределитель может выдать другой подходящий материал — для экспертизы используйте именно нужный случай.
6. При желании выберите ученика вверху и отправьте его независимый ответ. Задания и ответы каждого аккаунта хранятся раздельно.
7. Выберите аккаунт `-expert` в верхнем списке. Его пространство переключится автоматически. Откройте «Проверка эксперта» → «Открыть перевод текущего сценария». Общая очередь показывает только достаточно оценённые спорные случаи и может быть пустой после одного ответа — это нормально. Ручной ввод ID сохранён в блоке «Открыть по идентификатору». Случай, уже взятый другим экспертом, нельзя изменить до освобождения.
8. У одного варианта выберите «Основной допустимый». У остальных при необходимости — «Дополнительный допустимый» (максимум четыре), «Явно неверный» или «Не рассмотрен». Нажмите «Сохранить окончательное решение». Необязательно объявлять все остальные варианты неверными.
9. Вернитесь к участнику. Только теперь впервые нажмите «Открыть сегодняшний урок» в разделе «Практика перевода». Введите точный допустимый перевод и отправьте ответ. Для исходного фрагмента при принятии исходного перевода это `Здравствуйте`.
10. Выберите экспортёра и откройте «Выгрузка переводов», затем «Скачать переводы».

Подготовка создаёт реальные данные, ничего не удаляет и не меняет пороги согласования. На базе без школьного охвата ответы самостоятельных участников сами по себе не дадут принятие сообществом. Для короткого сквозного сценария используется штатное решение эксперта.

Если подготовка прервалась, уже созданные объекты останутся в базе, а успешно открытые сессии — в списке аккаунтов. ID видны в результатах и журнале. Можно закончить действия вручную; для новой независимой попытки задайте другой префикс. Не повторяйте подготовку с тем же префиксом: логины уже заняты. Если не удалась первоначальная установка пароля сотруднику, под администратором выдайте новый токен по его ID в разделе управления и установите пароль вручную.

## Ручные операции

| Аккаунт | Действия |
| --- | --- |
| Администратор | Создать школу, сотрудника, назначить/отозвать права, изменить политику, восстановить самостоятельного участника |
| Учитель | Создать класс в своей школе, ученика в своём классе, установить/восстановить пароль своего ученика |
| Поставщик | Передать фрагмент через форму «Поставка материалов» |
| Участник / ученик | Получить выдачу, подтвердить/исправить/пропустить, прочитать доступную статистику, выполнить дневные упражнения |
| Эксперт | Прочитать очередь, добавить вариант, сохранить итоговое решение, прочитать историю |
| Экспортёр | Получить и скачать JSON с переводами |
| Любой вошедший аккаунт | Свой профиль, свои сессии, смена собственного пароля, прогресс LMS |

После создания сотрудника/ученика его пароль устанавливается и сессия сохраняется автоматически, но текущий аккаунт не переключается. Выберите его вручную сверху. Для школ и классов используйте «Загрузить школы» / «Загрузить классы»: в формах появится выбор по названиям. Кнопка «Выбрать» в таблице подставит запись в связанные формы. После создания школы или класса они также подставляются автоматически. Идентификаторы случая и аккаунта остаются в технических данных и дополнительных формах восстановления/доступа.

Списки школ, классов, учеников и очередь показывают первые 100 записей; экспорт — первые 1000. Для более крупных выборок используйте API с offset/limit. Назначение прав и блокировка выполняются сервером, скрытие кнопок не используется как защита.

## Курсы LMS и дневной урок — разные вещи

В разделе «Вводный курс» нажмите «Открыть каталог курсов», затем название курса. Уроки можно читать без входа. Для сохранения прохождения выберите аккаунт и снова откройте курс. Кнопка «Завершить урок» сохраняет отметку. «Посмотреть мой прогресс» читает сохранённые отметки с сервера.

На пустой базе LMS создаёт вводный курс «Башкирский язык: первые шаги»: приветствие, благодарность, практика. Это текстовые карточки без проверки ответа. Фактический каталог может отличаться, если серверная база уже наполнена.

Дневной урок ядра состоит из упражнений по принятым переводам. Его состав фиксируется при первом запросе за день. Если запросить его до принятия материалов, он останется пустым до следующего дня. Для проверки в тот же день используйте другого участника, который ещё не открывал урок. Не меняйте дату и политику ради обхода этого правила.

Попытка упражнения сохраняется один раз. `recognized: true` означает точное совпадение с ключом, `false` — что текст отсутствует в ключе, а не лингвистический вердикт. Даже после `false` отправить другой ответ в то же упражнение нельзя. Обычная учебная попытка не создаёт голос и не меняет доверие.

## Ошибки и сессии

- `204` при выдаче — подходящих заданий нет: проверьте материалы, резервы, историю и квоты.
- `400` — неверные поля, пароль или настройки.
- `401` — войдите заново. Истёкший access token клиент один раз пробует обновить через ротацию refresh.
- `403` — выбран аккаунт без нужного права или доступа к конкретной школе/случаю.
- `404` — объект или маршрут отсутствует; убедитесь, что развёрнута актуальная версия API.
- `409` — конфликт: перечитайте случай/политику или проверьте, не отправили ли уже другой ответ.
- `429` — лимит регистрации, нужно подождать.
- HTML вместо JSON — проверьте маршруты Nginx: API-запрос не должен попадать в SPA.
- Сетевая ошибка/таймаут — изменение могло сохраниться. Сначала перечитайте состояние; создание объектов автоматически не повторяется.

Журнал в разделе «Проверка подключения» показывает методы, пути, статусы и ответы. Откройте «Журнал запросов». Пароли и токены скрыты. Технические ответы отдельных действий находятся под их понятным результатом в сворачиваемом блоке. Токен восстановления подставляется только в форму установки пароля в разделе «Доступ пользователей». После смены пароля прежние сессии отзываются.

Сессии аккаунтов хранятся в `sessionStorage` текущей вкладки, пароли не сохраняются. «Выйти» отзывает выбранную сессию на сервере. «Забыть все аккаунты вкладки» только удаляет локальные данные; серверные сессии при этом не отзываются. На другом домене и в другой вкладке войдите отдельно.

Чтобы дать доступ коллеге, отправьте адрес сайта: он может зарегистрировать обычного участника. Для экспертизы/поставки создайте ему отдельного сотрудника и передайте его логин/пароль лично. Не передавайте bootstrap-пароль администратора или signing key. На общедоступном стенде не оставляйте вкладку с сохранёнными административными сессиями.

Рабочий кабинет доступен по `/test/` на основном домене. LMS и экспертный клиент работают на своих поддоменах. SCORM-обёртка и Telegram-бот не входят в этот интерфейс; автоматическая передача прогресса во внешнюю LMS через SCORM здесь не реализована.
