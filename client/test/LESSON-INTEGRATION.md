# Уроки: инструкция интеграции из /test в React

Состояние кода на 14.11.2026. Краткий вход: [AI-HANDOFF.md](AI-HANDOFF.md).
Здесь описано существующее поведение; предложения на будущее вынесены в [BACKLOG.md](BACKLOG.md).

## 1. Термины и границы

| Термин | Значение в этом сценарии |
| --- | --- |
| Дневной урок / lesson | Сохранённый на день набор упражнений участника с финальным боссом |
| Упражнение / exercise | Учебное задание с условием и серверным ключом проверки |
| Вид / kind | Строковый код механики; состав урока не обязан включать все виды |
| Версия схемы / schemaVersion | Версия структуры условия и ответа конкретного вида |
| Попытка / attempt | Сохранённый учебный ответ; даже несовпавший с ключом завершает упражнение |
| Случай перевода / case | Материал, вокруг которого собираются варианты и решения о переводе |
| Выдача / assignment | Закреплённая за участником проверка перевода со сроком действия |
| Review | Подтверждение, исправление или пропуск выданного перевода; участвует в согласовании |
| Дневной босс | Review, привязанный к дневному уроку, после упражнений |

Не существует единого API «игровых уровней»: основная моковая карта содержит юниты/названия,
а реальный API пока выдаёт дневной контейнер. Соответствие карты и дневных уроков ещё нужно спроектировать.
Учебный ответ не создаёт голос и не меняет доверие. Review не возвращает учебную правильность.

## 2. Запуск и наблюдение

Из `client`: `npm ci`, затем `npm run dev`. Открыть адрес Vite с `/test/#learning`.
Оба входа собираются командой `npm run build` в одном `client/dist`.
Vite proxy: `/api`, `/auth`, `/health` → `CORE_API_URL` (по умолчанию `http://127.0.0.1:5105`),
`/api/lms` → `LMS_API_URL` (по умолчанию `http://127.0.0.1:5093`).

Без backend и входа: «Посмотреть все виды» → собрать ответ → «Посмотреть отправляемый ответ».
JSON появляется в технических данных; сетевой ответ в базу не отправляется. Preview босса отключён.
Настоящий сценарий: подготовить материалы по [USAGE.md](USAGE.md), войти, открыть сегодняшний урок.
Для словарных пар нужны пять однозначных словарных соответствий, для перевода — принятый перевод.
Пропуск и сборка требуют подходящего многословного исходника; аудио требует подготовки и хранилища.
Пустая выдача при недостатке материала — допустимый результат, а не основание подставлять мок.

## 3. Чтение JSON

`GET /api/lessons/today` с `Authorization: Bearer <JWT>` возвращает:

```json
{
  "id": "<lesson UUID>",
  "date": "2026-11-14",
  "exercises": [{
    "id": "<exercise UUID>",
    "original": "Һаумы!",
    "completed": false,
    "kind": "translation-text",
    "schemaVersion": 1,
    "prompt": {"text":"Һаумы!","sourceLanguage":"ba","targetLanguage":"ru"}
  }],
  "bossCompleted": false
}
```

Это схема с placeholders, не готовая выдача. Полные иллюстрации: [daily-lesson.json](src/examples/daily-lesson.json).
В старом preview-файле `bossCompleted` отсутствует; live DTO возвращает boolean. Preview использует его как false.

Правила парсинга:

- `prompt` — уже JSON-объект, второй `JSON.parse(prompt)` не нужен. В БД JSON хранится строкой, в публичном DTO это объект.
- Сначала проверить общую оболочку, затем выбрать обработчик по `kind` и числовому `schemaVersion`, затем проверить его `prompt`.
- Все шесть текущих видов используют версию `1`. Не выводить версию из наличия полей и не выбирать вид по индексу в массиве.
- ID считать непрозрачными строками. Для вариантов/слов отправлять выданные ID, не надписи и не позиции.
- Использовать порядок массива сервера; это не гарантия педагогической последовательности. Не пересоздавать задания на клиенте.
- `original` — поле совместимости; для скрытого исходника оно пустое. Основное условие находится в `prompt`.
- Для незнакомого вида/версии показать неподдерживаемое задание и возможность обновить клиент. Не отправлять ответ, не помечать выполненным, не разблокировать босса искусственно.
- Неизвестные дополнительные поля ответа сервера можно сохранять/игнорировать; это отличается от отправляемого `answer`, где лишние поля отвергаются.
- Выводить материал как текст (в `/test` используется `textContent`), в React — обычные текстовые узлы. Не вставлять полученное содержимое через HTML.

Рекомендуемый React интерфейс обработчика: `parsePrompt(raw)`, отображение, `buildAnswer(state)`.
Реестр индексировать парой вида и версии; экран урока отвечает за загрузку/сохранение/прогресс, обработчик — за свою механику.
Это рекомендация переноса: сейчас `/test` имеет `renderers[kind]`, общую проверку версии 1 и сборщики в `WeakMap` форм.
Каталог `GET /api/exercises/kinds` возвращает массив `{kind,schemaVersion}`; каталог не содержит автоматического описания UI.
Новый серверный вид потребует нового клиентского обработчика. В текущем `/test` список выбора статический (`exerciseKinds`).

## 4. Шесть механик: условие → внутренний answer

Каждый объект из правой колонки оборачивается **ровно один раз** в `{"answer": ...}`.
Маршрут общий: `POST /api/exercises/{exercise.id}/answer`.

| kind | Публичный prompt и поведение | Внутренний answer |
| --- | --- | --- |
| `translation-text` | `text`, `sourceLanguage`, `targetLanguage`; textarea перевода | `{"text":"Здравствуй!"}` |
| `word-match` | `left` и `right`: по 5 `{id,text}`; `languagePair`; выбрать соответствия | `{"pairs":[{"leftId":"l1","rightId":"r1"}, ...]}` |
| `audio-dictation` | `audioId`, `audioUrl`, языки совпадают; записать услышанное | `{"text":"Услышанный текст"}` |
| `audio-translation` | `audioId`, `audioUrl`, исходный и целевой языки; перевести услышанное | `{"text":"Перевод"}` |
| `missing-word` | `before`, `after`, `options:[{id,text}]`, `allowCustom`; показать пропуск между частями | `{"optionId":"g2"}` либо `{"text":"мәктәпкә"}` |
| `sentence-order` | `tokens:[{id,text}]`; пользователь задаёт порядок всех токенов | `{"tokenIds":["t1","t2","t3"]}` |

Для `word-match` ровно пять пар, каждый левый и правый ID используется один раз. Правильных пар в условии нет;
совпадение индексов массивов ничего не означает. В таблице `...` — сокращение, в JSON запроса нужны все пять пар.
Для `sentence-order` использовать все выданные ID один раз: одинаковые надписи остаются разными токенами.
Сервер допускает перестановку одинаковых по тексту вхождений, но не повтор одного ID.
В `missing-word` не объединять `optionId` и `text`; свой ввод доступен только при `allowCustom`.
Не удалять пробелы в `before/after`: они являются частью условия.
При текстовом вводе можно запретить пустой/пробельный ответ, но не менять регистр, пунктуацию или слова ради совпадения.
Текущее сравнение буквальное; семантическая проверка ИИ здесь не подключена.

Пример полного запроса и результата:

```json
{"answer":{"tokenIds":["t1","t2","t3"]}}
```

```json
{"id":"<attempt UUID>","recognized":false}
```

`id` результата — ID попытки, не упражнения. `recognized=false` означает «не совпало с сохранённым ключом».
Это успешное сохранение, после него `completed=true`; новая попытка с другим ответом для этой выдачи не разрешена.
Не показывать выдуманный правильный ответ: приватного ключа у клиента нет.
Повтор того же ответа возвращает ту же попытку, другой ответ после сохранения — 409.
Порядок массивов важен для повторной отправки; не менять сериализованный смысл ответа при сетевом повторе.
Прежний `/attempt` с `{"answer":"строка"}` оставлен только для `translation-text`; новый UI использует `/answer`.

## 5. Жизненный цикл и сетевые состояния

1. Загрузить урок. День определяет сервер (`Learning:TimeZone`, по умолчанию `Europe/Moscow`), не часы браузера.
2. Показать все задания, выполненные заблокировать. Количество и виды зависят от материала и настроек.
3. Собрать ответ, отключить повторную отправку на время запроса. Проверить, что аккаунт и упражнение ещё актуальны.
4. Отправить. После успеха перечитать `GET /api/lessons/today`, показать результат попытки.
5. Когда все упражнения `completed`, разрешить открыть босса. Завершение дня определять по `bossCompleted`.

`GET /lessons/today` создаёт и сохраняет дневной набор при первом чтении. Повторное чтение возобновляет его.
Для добавления конкретного вида: `POST /api/lessons/today/exercises`:

```json
{"kind":"missing-word","languagePair":"ba-ru","caseId":"<case UUID>"}
```

`caseId` необязателен для предложений. Для `word-match` его нужно **опустить**: код отвергает передачу `caseId`.
Без `caseId` запрос может вернуть уже сохранённое упражнение этого вида/пары; это не команда «новая попытка».
С `caseId` повтор того же материала/вида/пары также возобновляет снимок. Лимит контейнера — 100 упражнений.
Автоматический размер по умолчанию 10, но наличие десяти упражнений и всех шести видов не гарантируется.

| Ответ / состояние | Действие UI |
| --- | --- |
| 200 | Прочитать DTO; после изменения перечитать урок |
| 204 при выдаче | Не вызывать `response.json()` на пустом теле; подходящего задания нет |
| 400 | Показать ошибку структуры/параметров; не повторять автоматически тот же неверный запрос |
| 401 | Обновить сессию через существующий auth механизм; при неудаче предложить вход |
| 403 | Недостаточно прав; выбор рабочего пространства не выдаёт разрешения |
| 404 упражнения | Оно не найдено или принадлежит другому участнику; обновить контекст |
| 409 | Для ответа: уже сохранён другой ответ; для босса: ещё есть упражнения. Перечитать урок |
| Сеть / timeout | Исход операции может быть неизвестен; перечитать прогресс, сохранить исходный ответ для допустимого повтора |
| HTML вместо JSON | Проверить proxy/Nginx и URL; не интерпретировать HTML как пустой урок |

При смене пользователя очищать карточки и отбрасывать запоздавшие ответы запросов прежнего аккаунта.
`/test` помечает формы `data-actor` и проверяет его перед отправкой; при переносе отдельно защитить асинхронную загрузку.
Основной Zustand с локальными XP/пройденными моковыми уроками не заменяет прогресс API.
JWT пользователя используется для `/api`; сервисные Telegram/internal секреты не должны попадать в браузер.
Кабинет хранит свой контекст в `sessionStorage` (`bashperevod.workspace.v1`); копировать весь кабинетный state в React не требуется.

## 6. Аудио

Показывать `<audio controls preload="none">` по `prompt.audioUrl`. При отсутствии/ошибке ссылки предложить обновить урок.
Ссылка подписана и истекает; повторный GET урока выдаёт актуальную ссылку. Не переписывать её host/path/query.
`audioId` — идентификатор записи, не URL. Не конструировать адрес самостоятельно и не хранить подписанную ссылку как постоянную.
В preview реального аудио нет. При настоящей выдаче `/test` разрешает только http/https URL без credentials.
Автоматический урок использует подготовленное аудио; явная выдача аудиовида может запустить синтез.
В кабинете на такой запрос timeout 360 секунд против обычных 30; отмена браузерного запроса не доказывает отмену работы сервера.
Для реального звука нужны Silero/Python и MinIO; детали эксплуатации — в backend [EXERCISE-API.md](../../src/main-api/docs/EXERCISE-API.md).

## 7. Reviews и босс

`POST /api/reviews/next?kind=...` возвращает assignment: `id`, `caseId`, `variantId`, `original`,
`translation`, `expiresAt`, `kind`, `options:[{id,text}]`, `allowCustom`.
Без `kind` запрос сохраняет режим `translation-confirm`.
Активная выдача возвращается независимо от запрошенного режима: рендерить **полученный** `kind`.

| kind выдачи | UI | Тело `POST /api/reviews/{assignment.id}/response` |
| --- | --- | --- |
| `translation-confirm` | Оригинал и один перевод, подтвердить/исправить | `{"action":"Confirm"}` или `{"action":"Correct","correction":"Свой перевод"}` |
| `translation-choice` | От 1 до 4 вариантов; выбрать один или предложить свой | `{"action":"Confirm","selectedVariantId":"<option UUID>"}` или `{"action":"Correct","correction":"Свой перевод"}` |
| `translation-create` | Перевода ещё нет, только собственный ввод | `{"action":"Correct","correction":"Первый перевод"}` |

Для пропуска — `{"action":"Skip"}`. Не отправлять выбор и исправление вместе.
Результат: `{"responseId":"<UUID>","archived":false}`, без `recognized`.
`archived` не является показателем правильности. Фидбек нейтральный: ответ учтён.
Примеры: [review-choice.json](src/examples/review-choice.json), [review-confirm.json](src/examples/review-confirm.json).
Для `translation-create` кабинет сейчас строит preview из confirm-примера, отдельного JSON нет.

Босс: `POST /api/lessons/today/boss` после завершения упражнений. Полученную выдачу отправлять в `/reviews/{id}/response`.
`Confirm` и `Correct` завершают босса; `Skip` оставляет незавершённым.
204 означает уже пройденного босса **или** отсутствие подходящего материала: различать повторным GET урока по `bossCompleted`.
Пустой список упражнений сам по себе не означает завершённый день; сервер допускает запрос босса, если невыполненных упражнений нет.
Прогресс общий с Telegram. Не создавать локального босса из трёх моковых фраз.

Известный крайний случай текущего `/test`: `StartBossAsync` просит confirm, но общий allocator может вернуть активный
`translation-create`. `renderDailyBoss` обрабатывает choice, однако для create оставляет кнопку Confirm и пустой перевод.
При переносе использовать общий renderer reviews с явной веткой create. Исправление самого `/test` — отдельный пункт backlog.

## 8. Расширение без ломки старых выдач

На backend новый вид реализует `IExerciseHandler`: уникальный `Kind`, `SchemaVersion`, требования
`RequiresSentence/RequiresAudio/RequiresAcceptedTranslation`, `Create`, `Evaluate`.
Разделять публичное условие, приватный ключ и ответ. Сохраняются снимки, проверка использует выданный ключ.
Регистрация — `DependencyInjection.cs`; автоматическое включение — `Learning:Kinds`.
Новые источники данных могут потребовать расширить `ExerciseMaterial` и загрузку материалов.

При несовместимой смене схемы оставить старый handler зарегистрированным, добавить новую версию;
выдача использует latest, ответ на старое упражнение проверяется сохранённой версией.
На клиенте сохранить renderer старой версии и добавить новый. Не трактовать любую версию как последнюю известную.
Сервер может поддерживать больше видов, чем установленный клиент: fallback обязателен.
Для нового вида обновить пример, заголовок/каталог UI, сборщик ответа, документацию и проверки поведения.
Не создавать универсальный генератор форм или новую платформу плагинов только ради предполагаемых будущих видов.

## 9. Проверка переноса

Сверить все шесть отправляемых JSON с таблицей и интерактивным preview. На настоящих данных проверить:
сохранение несовпавшего ответа, обновление страницы, общий прогресс с ботом, повтор того же ответа и конфликт другого,
204, истёкшее аудио, неизвестную версию, переключение аккаунта во время запроса, все три режима review и босса.
Сборка — из `client`: `npm run build`. Она собирает оба UI.
В этой документационной задаче интеграция и живые сценарии заново не выполнялись.
