# Рабочий кабинет Башперевода — `/test/`

Основной React-интерфейс открывается на `/`. Рабочий кабинет существующего ядра и LMS доступен отдельно по `/test/`. Боковое меню кабинета показывает задачи выбранного рабочего пространства; на экране открыт один раздел.

Кабинет сохранён из последнего коммита NickFeD перед заменой фронтенда: `e8347fe` (после `8bcd17b`, «пред реализация»). После слияния `14e74a6` точка входа переключилась на React. Теперь все файлы кабинета собраны в `client/test/`. Страница `index.html` запускает локальный `src/workspace.js`; общий Vite собирает оба интерфейса в один `client/dist`.

- [Инструкция и полный сквозной сценарий](USAGE.md) — доступна также по ссылке в разделе «Как пользоваться» кабинета.
- `index.html` — вход рабочего кабинета по `/test/`.
- `src/workspace.js` — запросы, действия, переключение аккаунтов, ротация сессий.
- `src/workspace-layout.js` — страницы и формы.
- `src/workspace-view.js` — навигация, рабочие пространства, понятные результаты и выбор по названиям.
- `src/workspace.css` — адаптивное оформление кабинета.
- `../vite.config.js` — общая сборка и proxy для локальной разработки.

Из каталога `client`: `npm ci`, `npm run build`. Разработка: `npm run dev`. Существующий Dockerfile собирает оба интерфейса.

Пароли и серверные секреты в исходниках не задаются. Клиент использует относительные API-пути; авторизацию и области доступа проверяет сервер.

Самостоятельно зарегистрированного ученика можно пригласить по логину: учитель использует форму в «Школа и пользователи», ученик принимает или отклоняет приглашение в «Мой класс». Инструкция — в USAGE.md. Требуется версия ядра с миграцией `ClassInvitations`.

Выбор «Администратор», «Эксперт» и других пространств меняет только навигацию, не выдаёт права. JSON и журнал запросов находятся в сворачиваемых технических разделах. Порог согласования и правила обучения не менялись.

## Проверка новых заданий

Откройте `/test/#learning` → **«Посмотреть все виды»**: без входа отображаются шесть учебных механик. Можно собрать пары и предложение, выбрать пропущенное слово или ввести текст. Кнопка **«Посмотреть отправляемый ответ»** показывает подготовленный JSON в технических данных ответа; запрос в API не отправляется. Аудиофайлы в примерах не подключены.

После загрузки материалов войдите как участник и нажмите **«Открыть сегодняшний урок»**. В блоке **«Получить задание определённого вида»** можно запросить нужный `kind`, указать языковую пару и, кроме словарных пар, необязательный ID случая перевода. Задание сохраняется в сегодняшнем уроке. Отсутствие подходящего материала показывается сообщением; первый запрос озвучки может занять несколько минут. Для реального аудио серверу нужны модель Silero и настройка MinIO.

В `/test/#reviews` выберите режим: **популярные переводы** или **подтверждение одного перевода**. Кнопка **«Посмотреть пример»** работает без входа, **«Получить задание»** загружает настоящую выдачу. Для выбора отправляется один `selectedVariantId`, для своего варианта — только `correction`. Незавершённая выдача сохраняет исходный режим.

Все учебные ответы отправляются в `POST /api/exercises/{id}/answer`, мнения о переводах — в `POST /api/reviews/{id}/response`. Сохранённое упражнение блокируется, неподдерживаемые виды/версии не отправляются. Сервер определяет правильность; клиент не хранит ключей проверки.
