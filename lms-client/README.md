# Кабинет преподавателя LMS

В кабинете преподаватель управляет классами, видит учеников и их ответы, создаёт предложения с **предложенным** переводом и выдаёт задания. Свой перевод регистрируется в main-api как кандидат для проверки. Ученики получают только исходное предложение, без варианта ответа.

## Оценка и экспертиза

Отчёт по заданию каждый раз читает актуальное решение main-api. Пока переводу не присвоено решение, ответ ученика имеет статус «На проверке». После решения сообщества (на новой базе по умолчанию 300 независимых показов и не менее 51% поддержки с требуемым охватом школ и классов) или эксперта LMS сверяет ответ с принятыми вариантами, игнорируя регистр, пробелы и пунктуацию. Если эксперт утвердил несколько вариантов, любой из них считается верным. Преподаватель не назначает оценку вручную.

В разделе «Мои переводы» преподаватель может отправить запрос эксперту с пометкой. Пометка показывается в рабочем пространстве эксперта. Ответы и основание решения видны в отчёте и CSV. Для создания кандидатов и запроса экспертизы LMS API и main-api используют общий `INTERNAL_API_KEY` вместе с JWT преподавателя.

Ранее выданные задания на основе собственных переводов автоматически связываются с main-api при открытии класса, если исходный перевод ещё существует в LMS. Задания с удалённым исходным переводом остаются без автоматической оценки.

## Разработка

```bash
npm ci --prefix lms-client
npm run dev --prefix lms-client
npm run build --prefix lms-client
```

Vite проксирует `/auth` на локальное ядро (`localhost:8080`), `/api/lms` на LMS API (`localhost:8081`). В Compose фронтенд собирается отдельным Dockerfile и отдаётся Nginx.
