# Башперевод

Репозиторий объединяет школьное ядро перевода, веб-клиент и отдельный вводный LMS курс. Ядро заменено реализацией второго разработчика в коммите `017bbc2`; его фактический API и правила описаны в [src/main-api/START-HERE.md](src/main-api/START-HERE.md), [src/main-api/IMPLEMENTATION.md](src/main-api/IMPLEMENTATION.md) и [src/main-api/docs/VERIFICATION.md](src/main-api/docs/VERIFICATION.md).

## Состав

- `src/main-api` — новое ядро на .NET 10: аккаунты, авторизация, школы, выдача переводов, согласование, экспертиза, доверие, экспорт и базовые учебные попытки. В нём один Dockerfile и собственные миграции PostgreSQL.
- `client` — функциональный веб-интерфейс ядра и LMS: аккаунты, школы, материалы, ответы, экспертиза, упражнения, курсы и управление доступом. На обоих доменах открывается на главной странице. [Инструкция и сквозной сценарий](client/public/USAGE.md).
- `expert-client` и `src/expert-api` — отдельные клиент и API для `expert.bashperevod.ru`. Экспертный API пропускает только маршруты входа, экспертизы и общих настроек; права и данные проверяет ядро.
- `src/lms-api` — прежний отдельный сервис вводного курса и прогресса. Он проверяет JWT участника через `GET /api/me` ядра.
- `scorm` — SCORM 1.2 обёртка первого курса. [Сборка и ограничения](scorm/README.md).
- `src/telegram-bot` — прежний бот. Он ожидает удалённые внутренние маршруты и пока не адаптирован к новому ядру; в Compose запускается только с профилем `legacy-bot`.

## Совместимость и данные

Новый API не поддерживает старые `/api/auth/*`, `/api/tasks/*`, `/api/leaderboard` и `/api/internal/*`. Веб-клиент использует `/auth/register`, `/auth/sign-in`, `/api/reviews/next` и `/api/reviews/{id}/response`. Игровые баллы и рейтинг в новом ядре отсутствуют. LMS маршруты `/api/lms/*` идут напрямую в LMS API; они не добавлены внутрь ядра.

Новый `core-db` использует том `core_data`. Старый том `main_data_v2` Compose не подключает и не удаляет. Аккаунты, сессии и переводы из прежней базы автоматически не мигрируют. Прежний прогресс в LMS останется привязан к старым ID пользователей. Перед переходом пользователей на новое ядро нужна отдельная миграция данных или повторная регистрация.

## Запуск через Compose

В `.env` задайте `POSTGRES_PASSWORD`, `JWT_SIGNING_KEY` (постоянный секрет не короче 32 байт UTF-8) и `BOOTSTRAP_PASSWORD`. `BOOTSTRAP_USERNAME` по умолчанию `admin`. `BOOTSTRAP_PASSWORD` нужен при первом запуске пустой базы. Не меняйте `JWT_SIGNING_KEY` между развёртываниями: ранее выданные токены перестанут работать.

```bash
docker compose up -d --build
```

Nginx принимает `/auth/*`, `/api/*` и `/health/*`. Проверка готовности: `/health/ready`; проверка LMS: `/api/lms/health`. В Coolify доменам `bashperevod.ru`, `lms.bashperevod.ru` и `expert.bashperevod.ru` назначьте сервис `nginx` с внутренним портом 80. Если используется отдельный Caddy, [deploy/Caddyfile](deploy/Caddyfile) содержит все три домена. Прежний SCORM пакет находится в `bashperevod-scorm-1.2.zip`; текущий клиент не отправляет прогресс в его обёртку.

Проверка здоровья `nginx` проверяет главную страницу; состояние ядра и LMS проверяйте отдельно по их маршрутам. Поэтому недоступность LMS не исключает весь веб-сайт из маршрутизации Coolify.

Экспертный кабинет показывает спорные переводы после достижения `RequiredParticipants` ответов, если поддержка лидера ниже `SupportThreshold`. Эксперт берёт задачу в работу, может предложить свой вариант и принять решение. Закрытый перевод в очередь больше не попадает. Администратор меняет эти два порога в «Настройках» кабинета; остальные поля общей политики сохраняются. Для доступа нужен профиль `expert` или `administrator`, созданный в ядре.

Compose — интеграционная оболочка этого репозитория. Документация внутри `src/main-api` описывает самостоятельный запуск ядра без Compose. Перед реальным развёртыванием проверьте совместимость существующих клиентов и данных; тестовый Docker запуск в этом окружении не выполнен.
