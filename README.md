# Башперевод

Репозиторий объединяет школьное ядро перевода, веб-клиент и кабинет преподавателя LMS. Ядро заменено реализацией второго разработчика в коммите `017bbc2`; его фактический API и правила описаны в [src/main-api/START-HERE.md](src/main-api/START-HERE.md), [src/main-api/IMPLEMENTATION.md](src/main-api/IMPLEMENTATION.md) и [src/main-api/docs/VERIFICATION.md](src/main-api/docs/VERIFICATION.md).

## Состав

- `src/main-api` — новое ядро на .NET 10: аккаунты, авторизация, школы, выдача переводов, согласование, экспертиза, доверие, экспорт и базовые учебные попытки. В нём один Dockerfile и собственные миграции PostgreSQL.
- `client` — основной веб-интерфейс ядра на `bashperevod.ru`: аккаунты, школы, материалы, ответы, экспертиза, упражнения и управление доступом. [Инструкция и сквозной сценарий](client/public/USAGE.md).
- `lms-client` — React/Vite кабинет преподавателя на `lms.bashperevod.ru`: классы, переводы, задания, ответы и аналитика. [Как работать с отчётами](lms-client/README.md).
- `expert-client` и `src/expert-api` — отдельные клиент и API для `expert.bashperevod.ru`. Экспертный API пропускает только маршруты входа, экспертизы и общих настроек; права и данные проверяет ядро.
- `src/lms-api` — сервис классов, участников, собственных переводов, заданий, ответов и прежнего вводного курса. Он проверяет токен через `GET /api/me` ядра.
- `scorm` — SCORM 1.2 обёртка первого курса. [Сборка и ограничения](scorm/README.md).
- `src/telegram-bot` — студенческий бот на TelegramBotKit: профиль и прохождение ежедневных заданий нового ядра. Запускается с профилем Compose `telegram`. [Настройка и проверка](src/telegram-bot/README.md).

## Совместимость и данные

Новый API не поддерживает старые `/api/auth/*`, `/api/tasks/*`, `/api/leaderboard` и `/api/internal/*`. Веб-клиент использует `/auth/register`, `/auth/sign-in`, `/api/reviews/next` и `/api/reviews/{id}/response`. Игровые баллы и рейтинг в новом ядре отсутствуют. LMS маршруты `/api/lms/*` идут напрямую в LMS API; они не добавлены внутрь ядра.

В LMS каждый вошедший пользователь может работать как преподаватель со своими классами. Участника добавляют по логину существующего аккаунта ядра. Сервис LMS хранит классы, состав, задания и ответы в `lms-db`; предложенные преподавателем переводы регистрирует в main-api как кандидаты. Для отчётов LMS запрашивает актуальное решение ядра, поэтому оценки обновляются после решения сообщества или эксперта. Ученик видит только задания классов, в которые он добавлен, без варианта ответа. Интеграция с Яндексом запланирована отдельно.

Для каждого задания преподаватель видит группы «Все», «Участвовали» и «Не сдали», ответы учеников, принятый перевод и основание решения. Он может запросить экспертизу собственного перевода с пометкой. Оценку выставляет система по решению сообщества или эксперта; до решения ответы остаются без оценки. Задания и отчёт по классу выгружаются в CSV.

Новый `core-db` использует том `core_data`. Старый том `main_data_v2` Compose не подключает и не удаляет. Аккаунты, сессии и переводы из прежней базы автоматически не мигрируют. Прежний прогресс в LMS останется привязан к старым ID пользователей. Перед переходом пользователей на новое ядро нужна отдельная миграция данных или повторная регистрация.

## Запуск через Compose

В `.env` задайте `POSTGRES_PASSWORD`, `JWT_SIGNING_KEY` (постоянный секрет не короче 32 байт UTF-8) , `BOOTSTRAP_PASSWORD` и `INTERNAL_API_KEY` для связи LMS с ядром. `BOOTSTRAP_USERNAME` по умолчанию `admin`. `BOOTSTRAP_PASSWORD` нужен при первом запуске пустой базы. Не меняйте `JWT_SIGNING_KEY` между развёртываниями: ранее выданные токены перестанут работать.

```bash
docker compose up -d --build
```

Nginx направляет каждый домен в свой клиент: `bashperevod.ru` → `client`, `lms.bashperevod.ru` → `lms-client`, `expert.bashperevod.ru` → `expert-client`. Проверка готовности ядра: `/health/ready`; LMS: `/api/lms/health`. В Coolify всем трём доменам назначьте сервис `nginx` с внутренним портом 80. Если используется отдельный Caddy, [deploy/Caddyfile](deploy/Caddyfile) содержит эти домены. Прежний SCORM пакет находится в `bashperevod-scorm-1.2.zip`; текущий клиент не отправляет прогресс в его обёртку.

Проверка здоровья `nginx` проверяет главную страницу; состояние ядра и LMS проверяйте отдельно по их маршрутам. Поэтому недоступность LMS не исключает весь веб-сайт из маршрутизации Coolify.

Каждый активный пользователь ядра может войти в экспертный кабинет. В очереди первыми идут запросы преподавателей, затем переводы, где лидер получил недостаточную поддержку. Начальные личные пороги — от 300 ответов и поддержка лидера ниже 80%; каждый пользователь меняет их в «Настройках». Эти параметры влияют только на его экспертную очередь и не меняют общую политику согласования. Эксперт может выбрать любой предложенный вариант, добавить свой, отметить дополнительные допустимые и неверные переводы. Дашборд показывает общее число экспертных решений, доступный остаток и личный вклад; закрытый перевод в очередь не возвращается.

В экспертном кабинете вкладка **Загрузка CSV** принимает проверенные башкирско-русские переводы и фрагменты без перевода. Для загрузки нужна роль эксперта или администратора. [Формат файла, права и повторная загрузка](expert-client/CSV-IMPORT.md).

Compose — интеграционная оболочка этого репозитория. Документация внутри `src/main-api` описывает самостоятельный запуск ядра без Compose. Перед реальным развёртыванием проверьте совместимость существующих клиентов и данных; тестовый Docker запуск в этом окружении не выполнен.
