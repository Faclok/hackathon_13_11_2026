# Загрузка CSV в экспертном домене

## Временная загрузка словаря для сопоставления

В экспертном кабинете откройте **Словарь CSV**. Эта отдельная временная форма загружает слова в таблицу `VocabularyEntry` базы main-api, а не в таблицы фрагментов и переводов. Новый метод ядра и миграция БД не нужны: форма отправляет порции до 500 пар в существующий `POST /api/vocabulary`, разрешённый в прокси `src/expert-api/server.js` только для POST. JWT вошедшего пользователя передаётся без замены. По прямому указанию пользователя для этой временной загрузки убрана проверка `content.deliver`: достаточно любого активного аккаунта с действующей сессией, включая участника без роли поставщика данных. Проверка входа остаётся в общей группе `/api` main-api.

Файл: UTF-8 (BOM допустим), до 25 МБ и 20 000 строк. Первый столбец содержит башкирское слово, второй — русский перевод. Принимаются заголовки `word,translation` и `text_ba,text_ru`, а также файлы без заголовка. Разделители `,` и `;` определяются автоматически, поддерживаются CSV-кавычки. Каждое значение после удаления внешних пробелов должно быть одним словом, не длиннее 200 символов. Весь файл проверяется до первого запроса; при ошибках кнопка загрузки недоступна. Первые пять пар видны в предпросмотре.

```csv
text_ba,text_ru
бер,один
ике,два
өс,три
дүрт,четыре
биш,пять
```

Запрос в ядро:

```http
POST /api/vocabulary
Authorization: Bearer <accessToken>
Content-Type: application/json

{"languagePair":"ba-ru","entries":[{"word":"бер","translation":"один"}]}
```

Ответ ядра: `200 {"ids":["<VocabularyEntry.Id>"]}`. Повтор одинаковой пары возвращает прежний ID. Другой перевод того же слова добавляется отдельной парой. Повторы внутри CSV удаляются перед отправкой. Направление в этой форме фиксировано: `ba-ru`.

Загрузку можно остановить после текущей порции и повторить тем же файлом. Сохранённые порции остаются в БД; повтор не создаёт копий. При ошибке форма показывает диапазон строк неудачной порции и сохраняет число обработанных пар. Временная форма не изменяет генератор упражнений: для `word-match` нужны минимум пять различных слов и переводов; существующее ограничение выборки первых 500 записей и снимки уже выданных заданий сохраняются.

Чтобы удалить временную функцию: удалите `src/VocabularyImport.jsx`, `src/vocabulary-import.js`, `src/vocabulary-import.css`, `src/vocabulary-import.test.js`, импорт и вкладку `vocabulary` в `src/main.jsx`, строку `/api/vocabulary` в `../src/expert-api/server.js`, проверку маршрута в `../src/expert-api/server.test.js` и запись нового теста из `package.json`. Сам `POST /api/vocabulary` и таблицу в main-api удалять не нужно. Общий CSV-парсер по-прежнему используется штатным импортом фрагментов.

## Загрузка фрагментов и проверенных переводов

В экспертном кабинете выберите **Загрузка CSV**. Требуется учётная запись эксперта или администратора. Файл должен быть в UTF-8, размером до 25 МБ и содержать не более 20 000 строк. Поддерживаются кавычки, запятые и переносы строк в значениях.

Обязательные колонки: `fragment_id`, `text_ba`, `source_dataset`. Если есть колонка `text_ru`, её значение обязательно в каждой строке: пара сразу сохраняется как проверенная экспертом, а конкретный эксперт в решении остаётся `null`. Если колонки `text_ru` нет, создаётся кейс с пустым служебным вариантом. Участники могут предложить перевод через `POST /api/reviews/next?kind=translation-create`; подтверждать пустой вариант нельзя. Такие записи доступны в `GET /api/expert/untranslated`; эксперт может сразу добавить проверенный перевод через `POST /api/expert/fragments/{fragmentId}/translation` с телом `{"translation":"..."}`. В этом случае решение связывается с вошедшим экспертом.

При запуске обновлённого API миграция создаёт такие кейсы и для ранее загруженных строк без перевода. Повторно загружать CSV не требуется.

Остальные колонки сохраняются в `source.chapter` как JSON; `source_dataset` становится `source.document_id`, а `attribution` — названием источника. Роль качества или лицензии не меняется автоматически.

Кабинет отправляет записи по одной через `POST /api/expert/imports`. Повтор тех же строк под тем же аккаунтом возвращает прежний результат без дублей. Изменённая запись с прежним `fragment_id` вызывает конфликт. Основной домен не публикует эти маршруты. LMS домен публикует обычный `POST /api/deliveries` для непроверенных кандидатов.

Для командной загрузки двух файлов используйте `scripts/import_fragments.py`. Сначала запустите без `--execute` для проверки. Для записи передайте `--execute` и переменные `EXPERT_API_USERNAME`/`EXPERT_API_PASSWORD` либо `EXPERT_API_TOKEN` (при необходимости с `EXPERT_API_REFRESH_TOKEN`). Скрипт не печатает секреты и может быть повторён после сбоя.
