# Загрузка CSV в экспертном домене

В экспертном кабинете выберите **Загрузка CSV**. Требуется учётная запись эксперта или администратора. Файл должен быть в UTF-8, размером до 25 МБ и содержать не более 20 000 строк. Поддерживаются кавычки, запятые и переносы строк в значениях.

Обязательные колонки: `fragment_id`, `text_ba`, `source_dataset`. Если есть колонка `text_ru`, её значение обязательно в каждой строке: пара сразу сохраняется как проверенная экспертом, а конкретный эксперт в решении остаётся `null`. Если колонки `text_ru` нет, создаётся кейс с пустым служебным вариантом. Участники могут предложить перевод через `POST /api/reviews/next?kind=translation-create`; подтверждать пустой вариант нельзя. Такие записи доступны в `GET /api/expert/untranslated`; эксперт может сразу добавить проверенный перевод через `POST /api/expert/fragments/{fragmentId}/translation` с телом `{"translation":"..."}`. В этом случае решение связывается с вошедшим экспертом.

При запуске обновлённого API миграция создаёт такие кейсы и для ранее загруженных строк без перевода. Повторно загружать CSV не требуется.

Остальные колонки сохраняются в `source.chapter` как JSON; `source_dataset` становится `source.document_id`, а `attribution` — названием источника. Роль качества или лицензии не меняется автоматически.

Кабинет отправляет записи по одной через `POST /api/expert/imports`. Повтор тех же строк под тем же аккаунтом возвращает прежний результат без дублей. Изменённая запись с прежним `fragment_id` вызывает конфликт. Основной домен не публикует эти маршруты. LMS домен публикует обычный `POST /api/deliveries` для непроверенных кандидатов.

Для командной загрузки двух файлов используйте `scripts/import_fragments.py`. Сначала запустите без `--execute` для проверки. Для записи передайте `--execute` и переменные `EXPERT_API_USERNAME`/`EXPERT_API_PASSWORD` либо `EXPERT_API_TOKEN` (при необходимости с `EXPERT_API_REFRESH_TOKEN`). Скрипт не печатает секреты и может быть повторён после сбоя.
